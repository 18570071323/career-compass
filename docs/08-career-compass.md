# 08 求职端小程序「简历罗盘」产品方案

> 状态：需求已确认并已对齐校招求职功能（docs/07）。AppID：`wx3d09f84d9f829852`（个人主体）。
> 求职导航 = 网站问卷式职业规划；小程序三个功能与网站求职端语义一致（含"每个方向出优化/报告"）。

## 1. 定位与主体

- **名称**：简历罗盘（英文 CareerCompass）
- **形态**：微信小程序，**个人主体**开发经营（微信已支持个人小程序上架经营）
- **与 B 端关系**：两端分开。B 端 = 现有「简历智配」SaaS（企业招聘方，网页端）；
  C 端 = 简历罗盘（求职者，小程序）。**共用同一套 AI 引擎**（文档解析 + DeepSeek 解析/评分/报告/深度分析）。
- 定位语：**一份简历，看清方向，走对第一步**

## 2. 功能与免费策略（已确认）

| 功能 | 免费策略 | 说明 |
|---|---|---|
| ① 职业方向匹配 | 见"免费额度" | 简历 → 推荐 3-4 个适配职业方向 |
| ② 岗位匹配分析 | **免费体验首选** | 简历 × 岗位 → 匹配报告 + 简历优化建议 |
| ③ 求职导航 | 见"免费额度" | 个性化求职行动路线 |
| ④ 更多分析 | **按次数收费** | 次数包：单次 ¥9.9 / 10 次 ¥69 / 50 次 ¥299 |

**免费额度（总池 1 次）**：新用户共 **1 次免费体验**，三个功能任选其一消耗；
产品主推把这一次用在②岗位匹配报告（旗舰）。之后全部按次数包扣费。

**不做的功能**：公司避雷清单 ❌、新职业方向推荐 ❌（保持轻量）。

## 3. 收费模型

- **按次数**，非订阅。次数包购买后进入"我的额度"。
- 免费额度为**总池 1 次**（三个功能任选其一）；每做一次"方向匹配 / 岗位匹配 / 求职导航"消耗 1 次。
  方向匹配为**捆绑体验**：本次结果内的方向报告与逐方向优化不再额外扣次。
- 支付渠道（个人主体受限，按可用性演进）：
  - 阶段一（上架起步）：免费体验 + **人工开通次数包**（客服收款码/微信小商店），额度后台发放
  - 阶段二：微信开放个人主体支付能力后接入自动支付（JSAPI + 回调），计费接口已预留可插拔
- **管理后台（已实现）**：Web 控制台「小程序用户」页（仅企业管理员可见）——
  按 openid/昵称搜索 C 端用户、查看额度/免费池/是否有简历、发放次数包（写流水可对账）、重置免费体验；
  接口 `/api/v1/admin/mp/*`（users / grant / reset-free / logs），管理员 `User.role=admin` 方可调用。

## 4. 引擎新增能力（已实现并冒烟通过 ✅）

小程序与网站求职端（docs/07）共用同一套引擎，语义一一对应：

1. **方向匹配** `POST /api/v1/mp/direction-match`：简历（+top_n）→ 方向列表（rank/score/命中-缺失技能/理由/核心技能/工具链），
   确定性打分（无 JD 也适用，复用岗位库方向画像）。本次消耗 1 次额度（免费池或次数包），并缓存本次简历供后续深析。
2. **方向报告（无 JD 五维报告）** `POST /api/v1/mp/direction-report`：对某方向做 岗位匹配报告（无需手动贴 JD），
   以方向画像为伪 JD 出五维评分 + 完整 Markdown 报告（经验/技能/项目/差异化/成长）。
3. **按此方向优化** `POST /api/v1/mp/direction-optimize`：针对该方向的简历优化建议（复用网站 resume_analyze：
   总评/完整性/分维度建议/高性价比改动/参考写法/详略建议/风险提示）。**精简口径**：只列"不足→具体动作"，达标项不展示，
   各块去重并限条数，正文 ≤600 字（引擎层过滤兜底，B 端同源受益）。
4. **求职导航（问卷式职业规划，同网站）** `POST /api/v1/mp/career-plan`（+`GET /career-directions`、`GET /direction-profile` 支撑问卷）。
5. **岗位匹配报告（JD 版）** `POST /api/v1/mp/match-report`：简历 × 岗位 JD → 四维评分报告 + 简历优化建议（旧 `/guide` 遗留勿用）。

> 扣次规则已验证：免费额度总池 1 次优先 → 次数包 → 402；**分析成功才扣次**（失败不扣）。
> **捆绑体验（用户已确认）**：方向匹配（消耗 1 次额度）返回一次性 `session`；其结果页内的「方向报告」与
> 「按此方向优化」携带该 session 调用 = 已包含在本次方向匹配内，**不重复扣次**（一次匹配即一次完整体验，
> 可逐个方向查看报告/优化）。session 不存在或不匹配时才按次收费兜底。

## 5. 技术方案（小程序）

- **前端**：原生微信小程序（或 uni-app 双端备用）——页面：
  首页(上传简历) → 方向匹配结果 → 选岗位/录入 JD → 匹配报告页 → 求职导航页 → 我的(剩余次数/购买/订单)
- **账号**：wx.login() → code → 后端 jscode2session 换 openid → openid 即用户（个人主体无企业租户）
- **后端**：复用 apps/api；新增 C 端用户表 + 次数额度表 + C 端计费；走同一引擎
- **联调域名**：个人主体小程序正式版要求 **已备案域名 + HTTPS**；开发阶段用"不校验合法域名"直连测试后端
